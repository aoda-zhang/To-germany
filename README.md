## 德国 IT 求职整体规划（至 2027 年 2 月）

### 总体背景与定位

- 目标时间：2027 年 2 月，持德国机会卡赴德找 IT 工作
- 工作经验：8 年，全栈开发（偏前端）
- 技术定位：
  - 主线岗位：Senior Frontend Developer / Frontend-leaning Full-Stack Developer
  - 技术重点：React + TypeScript + 前端架构设计
  - 后端策略：Node.js / NestJS（以“面试与工作够用”为目标，不走纯后端路线）
- 语言现状与目标：
  - 英语：当前约 B1，目标达到稳定 B2（可顺畅完成技术 + 行为面试）
  - 德语：A0 起步，目标 A2（生活 + 求职基础）

### 月度执行计划

#### 2026 年 2 月｜定位与基础盘点

**德国 Senior 标准目标**
- 明确目标岗位的能力边界（不仅是“会写代码”，而是“能设计与决策”）
- 建立与德国 Senior Frontend / Full-Stack JD 一一对应的能力框架

**技术行动（Senior 维度）**
- 梳理并书面化以下能力：
  - React：渲染机制、Hooks 原理、性能优化策略
  - TypeScript：类型建模能力（不是语法）
  - 前端架构：模块拆分、依赖方向、shared 边界
  - 工程化：Monorepo、CI、Lint、质量保障
- 针对每一项写清：
  - 我在真实项目中做过什么
  - 为什么这么做（trade-off）

**语言行动**
- 英语：
  - 每周 3 次，完整讲一个项目（背景 → 决策 → 结果）
- 德语：
  - A0：发音、问候、自我介绍

**产出（必须完成）**
- 《德国 Senior Frontend 能力对照表》
- 《个人技术差距与补强清单》

#### 2026 年 3 月｜前端能力强化 I

**德国 Senior 标准目标**
- 能解释“为什么这样设计前端架构”，而不是只描述实现

**技术行动**
- React 深度：
  - Render 流程、Reconciliation、memo 使用边界
  - 性能问题的定位与度量思路
- 状态与数据层：
  - React Query 缓存设计
  - Error / Loading 的全局策略
- 架构：
  - App / Domain / Shared 的职责划分

**面试表达训练**
- 英语：
  - Explain a complex frontend architecture
- 德语：
  - 日常生活与简单技术名词认知

**产出**
- 英文《前端架构设计说明文档》
- 一张“前端分层架构图”

#### 2026 年 4 月｜前端能力强化 II + 项目打磨

**德国 Senior 标准目标**
- 项目能作为“技术决策样本”而不是 Demo

**技术行动**
- 对现有项目进行 Senior 化改造：
  - 为什么使用 Monorepo
  - Shared 如何控制依赖
  - 错误、日志、国际化策略
- 明确“不做什么”和原因

**面试准备**
- 英语：
  - 用 STAR 法完整讲 3 个项目
- 德语：
  - A1 语法（现在时、动词变位）

**产出**
- 可投递级 GitHub 项目
- 英文项目决策说明

#### 2026 年 5 月｜后端补强（够用即可）

**德国 Senior 标准目标**
- 后端体现“系统意识”，而不是 API 拼接

**技术行动**

  - 模块边界

- API 设计：
  - REST 语义
